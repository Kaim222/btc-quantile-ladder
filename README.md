# BTC Quantile Ladder

A passcode-gated static site in `index.html`: React with browser Babel and inline styles; no build step.

- **Ladder:** monthly-close instrument bands, standard/weighted power-law model, strikes, projections, lookup and chart.
- **MSTX:** monitor lag, level, alert log, gap chart, what-if inputs and collapsed evidence.
- **Playbook:** next action, open spreads, LEAPS units and weekly MACD.

Data and writers:

- `data/ladder-rules.json`: operator-maintained doctrine and sizing.
- `data/paper-ledger.json`: operator-maintained positions, phases, settlement values and routes.
- `data/playbook.json`: generated by `tools/playbook_refresh.py` (manual refresh).
- `data/iv-ledger.json`: accumulated by that refresh tool; an input to its IV calculations.
- `data/leaps-cost.json`: generated by `tools/leaps_cost.py`, including the `unit_at` price curve.
- `data/mstr-config.json`: operator-maintained thresholds, gates, slopes and holdings overrides; shared with the monitor.
- `data/mstr-model.json`: model/backtest snapshot; its generator is not included here. `tools/apply-evidence-block.py` updates its evidence block.

`tools/playbook_refresh.py` uses `tools/playbook_rules.json` and `tools/events.json`.
`tools/audit-2026-09-18/DECISIONS.md` records the cleanup specification.
Serve locally with `python -m http.server`; the browser normally loads CDN libraries and market feeds.

The separate [btc-monitor repository](https://github.com/Kaim222/btc-monitor) runs the alert monitor.
It writes `mstr_state.json` (including `last_run`) and `mstr_ledger.json`, fetched by the MSTX tab.
Notifications originate in that repository, not this site.
